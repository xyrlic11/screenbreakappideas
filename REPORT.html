the one idea

ข้ามได้เสมอ แต่ต้องจ่าย

แอปเตือนพักสายตามีเป็นสิบตัว ที่ต่างคือกลไกตอนคุณกดข้าม ปุ่ม Skip อยู่มุมล่างขวา ต้องกดค้าง 5 วินาที — นานพอให้ต้องตัดสินใจ สั้นพอที่จะไม่ใช่การแกล้ง

ปุ่มฉุกเฉินอยู่มุมล่างซ้าย คนละฝั่ง กดครั้งเดียวปิดเลย ไม่มีต้นทุน — จงใจ เพราะทางหนีที่คนกลัวจะกด คือทางหนีที่คนจะหาวิธีอ้อม แล้วระบบต้นทุนทั้งหมดก็เหลือแค่ฉากหน้า เปลี่ยนเป็นบันทึกไว้แล้วโชว์ในหน้าสถิติแทน

enforcement

เลือกได้ว่าจะให้บังคับแค่ไหน

ตั้งแยกกันระหว่างพักสายตากับพักยาว นี่คือฟีเจอร์ที่เพิ่มล่าสุด

โหมด เกิดอะไรขึ้น ข้ามยังไง มีใน
overlay เต็มจอ บังทุกอย่างรวม taskbar (ค่าเริ่มต้น) กดค้าง 5 วิ ทั้งคู่
popup การ์ดมุมจอ ตัวนับและกิจกรรมเดียวกัน ไม่แย่ง focus ไม่บังอะไร คลิกที่การ์ด ทั้งคู่
lock LockWorkStation() ต้องพิมพ์รหัสผ่านใหม่ ปลดล็อคก่อนเวลา — บันทึกเป็น skipped พักยาว

พักสายตาตั้งเป็น lock ไม่ได้ตั้งใจ — ล็อคจอเพื่อพัก 20 วินาที เสียเวลาพิมพ์รหัสผ่านนานพอๆ กับเวลาพัก

โหมด popup ไม่ใช่ของถูกลด

พักครบในโหมดนี้นับเป็นพักครบเหมือนกัน แต่ฐานข้อมูลบันทึกไว้ว่า แต่ละรอบใช้โหมดไหน สองอย่างนี้จะได้ไม่ปนกันเงียบๆ และตั้งพักยาวเป็น popup จะข้ามนับถอยหลัง 60 วินาทีไปด้วย — นับถอยหลังมีไว้ให้เซฟงานก่อนจอหาย การ์ดมุมจอไม่ได้เอาอะไรไป

architecture

ชั้นเดียวที่ตัดสินใจ ชั้นเดียวที่วาด

ทุก 1 วินาที: อ่าน sensor → อัปเดต state → ถาม policy → สั่ง UI ทางเดียว ไม่ย้อนกลับ

sensors idle time, lock state, ช่องโหว่ใน tick stream
state นับเวลาอยู่ไหม นับไปเท่าไรแล้ว
policy ถึงเวลาพักหรือยัง ต้องทำอะไร
commands start_break, show_toast, lock_workstation
ui วาดตามที่ถูกสั่ง ไม่นับเวลาเอง

กล่องสีคือ blink/core/ — import แค่ stdlib ไม่มี Qt ไม่มี Win32 และไม่เคยอ่านนาฬิกา เวลาถูกส่งเข้ามาเป็น parameter

ถาม UI ว่าอีกกี่นาทีจะถึงเวลาพัก มันตอบไม่ได้ — มันรู้แค่ว่า ถูกสั่งให้วาดอะไรล่าสุด ข้อจำกัดนี้แหละที่ทำให้เทสต์เวลาได้จริง และทำให้โหมด overlay กับ popup ส่ง command ชุดเดียวกันเป๊ะ

สามบั๊กที่เจอตอนเอา core ไปรันจริง

เพราะ blink/core/ เป็น stdlib ล้วนจริง ผู้รีวิวยกทั้งแพ็กเกจ ไปรันในคอนเทนเนอร์ Linux ได้โดยไม่แก้อะไรสักบรรทัด — ข้อดีของการแยกชั้น ที่ตั้งใจไว้ กลับกลายเป็นสิ่งที่ทำให้บั๊กถูกจับได้

critical   Win+L วินาทีเดียว ล้างเวลาทั้งหมดฟรี

จ้องจอ 1,000 วินาที แล้วล็อคจอ 1 วินาที → ตัวนับเหลือ 0 ทั้งคู่ กด Win+L ทุกชั่วโมงครึ่งก็ไม่ต้องเจอพักยาวอีกเลย และเพราะ OpenInputDesktop ล้มเหลวตอนขึ้น secure desktop ด้วย ทุก UAC prompt จึงล้างเวลาทิ้งเงียบๆ

ที่ต้องพูดตรงๆ: test_locked_screen_freezes_and_resets เขียนล็อกพฤติกรรมผิดนี้ไว้พอดี — ไม่ใช่ลืมเทสต์ แต่เป็นการตัดสินใจที่ผิดแล้วถูกตรึงด้วยเทสต์ ซึ่งอันตรายกว่าไม่มีเทสต์

แก้ — ล็อคจอ = แช่ตัวนับทันที แต่รีเซ็ตต่อเมื่อล็อคนานถึง เกณฑ์เดียวกับลุกไปพัก แยกเทสต์เดิมเป็นสองตัวที่พูดคนละเรื่อง

minor   counter_reset ยิงวินาทีละครั้ง

ลุกไปกินข้าว 10 นาที = 600 event สำหรับเหตุการณ์เดียว ตอนนี้ยังไม่เจ็บ เพราะฐานข้อมูลเก็บแค่ break แต่พอต่อ event log เข้า SQLite ตามแผนเฟส 2 ตารางจะบวมทันที แก้ — ประกาศเฉพาะตอนที่ล้างของจริง

high   ล็อคจอจริง ไม่ได้บังคับอะไรเลย

รอบพักยาวถูกล้าง ก่อน สั่งล็อค ปลดล็อคหลัง 3 วินาที = ได้เครดิตพักยาว 5 นาทีเต็ม โหมดที่หนักที่สุดในแอป กลายเป็นโหมดที่หลบง่ายที่สุด

แก้ — มองการล็อคเป็น คำขอ ไม่ใช่ ผลลัพธ์ สั่งแล้วเฝ้าดูว่าจอดำครบเวลาจริงไหม กลับมาก่อนเวลายังรีเซ็ตรอบให้ (ไม่งั้นเด้งซ้ำทันทีที่นั่งลง) แต่บันทึกเป็น skipped
